
# Lý thuyết

- Tư tưởng
	- Trong quá trình tìm kiếm, ưu tiên "**chiều sâu**" hơn "**chiều rộng**"
	- Đi xuống **sâu nhất** có thể trước khi quay lại

- Thuật toán
>DFS với đệ quy
```
DFS(u) {
	<Thăm đỉnh u>;
	chuaxet[u] = false;
	for (v in Ke(u)) {
		if (chuaxet[v])
			DFS(v)
	}
}
```

>DFS với ngăn xếp
```
DFS(u) {
	stack = {}; // Khởi tạo ngăn xếp rỗng
	push(stack, u); // Đưa u vào ngăn xếp
	<Thăm đỉnh u>;
	chuaxet[u] = false;

	while (!stack.empty()) {
		s = stack.top(); // lấy đỉnh ở đầu ngăn xếp
		found = false; // Cờ đánh dấu tìm thấy đỉnh kề chưa xét
		for (t in Ke(s)) {
			if (chuaxet[t]) {
				<Thăm đỉnh t>;
				chuaxet[t] = false;
				push(stack, t);
				found = true;
				break;
			}
		}
		
		if (!found) {
			stack.pop(); // Nếu không còn đỉnh kề thì xóa đỉnh đang xét 
		}
	}
}
```

- Độ phức tạp của DFS(u) phụ thuộc vào phương pháp biểu diễn đồ thị
	- Biểu diễn bằng ma trận kề: $O(n^2)$ với $n$ là số đỉnh
	- Biểu diễn bằng danh sách cạnh: $O(n.m)$ với $n$ là số đỉnh, $m$ là số cạnh
	- Biểu diễn bằng danh sách kề: $O(\max(n,m))$ với $n$ là số đỉnh, $m$ là số cạnh

- Ví dụ: Cho đồ thị gồm 13 đỉnh, kiểm tra DFS(1)
