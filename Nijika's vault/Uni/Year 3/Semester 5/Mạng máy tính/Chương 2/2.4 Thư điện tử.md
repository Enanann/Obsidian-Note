# SMTP

### Khái niệm

- Thư điện tử (electronic mail -> e-mail) gồm 3 thành phần chính
	- **user agents**
	- **mail servers**
	- **SMTP** (Simple mail transfer protocol)

1. User agents
- Cho phép người dùng đọc, trả lời, chuyển tiếp, lưu và tạo tin nhắn e.g. Microsoft Outlook, Apple Mail
- Tin nhắn được gửi đến **mail server** của người dùng

2. Mail servers
- Chứa các tin nhắn được gửi đến từ người dùng -> Lưu trong hàng đợi các tin nhắn đợi chuyển đi (**message queue**)
- Có **mailbox** -> Chứa các tin nhắn được gửi đến người dùng 

3. SMTP
- Là giao thức chính trong tầng ứng dụng cho email 
- Sử dụng TCP để gửi tin nhắn từ mail server của người gửi -> người nhận
- Gồm
	- Client side: Chạy trên mail server của người gửi, 
	- Server side: Chạy trên mail server của người nhận
-> mail server chứa cả 2 phần, thay đổi tùy vào là người gửi hay nhận

![[Pasted image 20250917162905.png]]

- Ví dụ A gửi 1 tin nhắn đến B:
	- A gọi user agent cho email, cung cấp địa chỉ email của B, viết tin nhắn và hướng dẫn user agent gửi tin
	- User agent của A gửi tin đến mail server của A -> đặt trong messaage queue
	- Client side của SMTP (trên mail server của A) thấy tin nhắn -> Mở kết nối TCP tới SMTP server chạy trên mail server của B
	- Sau khi handshaking, gửi tin nhắn của A vào kết nối TCP
	- Server side của SMTP tại mail server B nhận tin nhắn -> đặt vào mailbox
	- B gọi user agent để đọc tin nhắn tùy ý

### So sánh với HTTP

- Cả 2 đều dùng để gửi file từ một host này sang host khác
	- HTTP: Truyền files (đối tượng) từ Web server -> Web client
	- SMTP: Truyền files (tin nhắn e-mail) từ Mail server -> Mail server 

- SMTP sử dụng kết nối bền vững 
- SMTP sử dụng `CRLF.CRLF` để xác định điểm kết thúc của thông điệp

- Điểm khác biệt
	- **HTTP**: Pull protocol - ai đó tải thông tin lên web server, sau đó người dùng dùng HTTP để pull thông tin từ server theo ý muốn
	- **SMTP**: Push protocol - mail server gửi sẽ push file đến mail server nhận (cụ thểm kết nối TCP sẽ được tạo bởi máy muốn gửi file)
	- SMTP yêu cầu thông điệp (header & body) phải ở dạng ASCII 7-bit, HTTP không bị giới hạn này
	- HTTP đóng gói mỗi đối tượng (text, ảnh) trong **một thông điệp phản hồi HTTP rieeng**
	- SMTP đặt **tất cả các đối tượng vào một thư duy nhất**   

# Định dạng thông điệp thư 

- Khi gửi snail-mail (thư bình thường) thì sẽ có header chứa thông tin như địa chỉ người nhận, ngày gửi, địa chỉ gửi, etc... Tương tự, khi gửi e-mail thì phần header cũng sẽ có những thông tin như trên -> Được định nghĩa cấu trúc qua RFC 5322
- Thường thì có dạng như này:
```
From: alice@crepes.fr
To: bob@hamburger.edu
Subject: Searching for the meaning of life.
```
- Sau header, có một dòng trống; và sau đó là phần thân tin nhắn (ASCII)

# Giao thức truy nhập thư 

- Khi gửi email, tin nhắn sẽ từ user gửi gửi đến mail server của người gửi (để mail server có thể liên tục gửi đến mail server của người nhận khi client tắt máy). Tuy nhiên, client nhận sẽ không thể trực tiếp lấy thư đến do SMTP là push operation => **Sử dụng giao thức truy nhập thư** (POP3, IMAP, HTTP)

### POP3 - Post Office Protocol Version 3

- Bắt đầu khi client mở kết nối TCP đến mail server ở cồng 110 
=> 3 giai đoạn: authorization, transaction, update 

- Authorization:
	- Các lệnh của client:
		- `user`: Khai báo tên người dùng
		- `pass`: Mật khẩu
	- Các đáp ứng của server:
		- `+OK`
		- `-ERR`
```
S: +OK POP3 server ready
C: user bob
S: +OK
C: pass hungry
S: +OK user successfully logged on
```

- Transaction:
	- `list`: Liệt kê các số thông điệp
	- `retr`: trích xuất thông điệp theo số
	- `dele`: xóa
	- `quit`
```
C: list
S: 1 498
S: 2 912
S: .
C: retr 1
S: <message 1 contents>
S: .
C: dele 1
C: retr 2
S: <message 2 contents>
S: .
C: dele 2
C: quit
S: +OK POP3 server signing off
```

- Update: Thực hiện sau lệnh `quit`, kết thúc session POP3, server xóa tin nhắn được đánh dấu xóa 

- Ví dụ trước dùng POP3 với chế độ “tải và xóa”
- Bob không thể đọc lại thư nếu thay đổi client
- POP3 với chế độ “tải và lưu giữ”: sao các thông điệp lên các client khác nhau
- POP3 không giữ trạng thái của các phiên làm việc

### IMAP - Internet Mail Access Protocol

- Lưu giữ tất cả các thông điệp tại một nơi là server
- Cho phép người dùng tổ chức các thông điệp theo dạng các thư mục
- Lưu giữ trạng thái của người dùng qua các phiên làm việc:
	- Đặt tên thư mục và ánh xạ giữa các ID của thông điệp với tên thư mục
