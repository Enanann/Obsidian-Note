# Giới thiệu

- Giống như con người có thể được nhận dạng qua nhiều cách (tên, ngày sinh, mã công dân,...), Internet host cũng có thể được nhận dạng qua nhiều cách
- Một cách là **hostname** e.g. `cnn.com`, `youtube.com` -> Chúng là thuật ngữ gợi nhớ để cho con người dễ nhớ -> Gần như không cung cấp thông tin gì về địa điểm host (trường hợp kết thúc như `.vn`, `.fr` chỉ cung cấp quốc gia chứ không có gì thêm)
- **hostname** có thể có độ dài khác nhau và gồm các chữ cái -> Khó để xử lý bởi router. Vì những lý do trên, host còn được phân biệt qua **IP addresses** 

- Địa chỉ IP bao gồm 4 bytes và có cấu trúc phân cấp
- Địa chỉ IP 32 bit sẽ có dạng `121.7.106.83` với mỗi số nằm trong khoảng 0->255
- Nói địa chỉ IP có cấu trúc phân cấp tức là khi ta quét lần lượt các byte từ trái qua phải, ta nhận được thêm chi tiết thông tin về host 

# Hệ thống tên miền (DNS)

- Để hòa giải giữa cách dùng hostname của con người và IP address bởi máy tính, ta sẽ cần một dịch vụ có nhiệm vụ dịch hostname sang địa chỉ IP => Nhiệm vụ chính của DNS

- DNS là:
	- Hệ thống phân tán được thực hiện theo phân cấp của DNS server 
	- Giao thức tầng ứng dụng cho phép host truy vấn cơ sở dữ liệu phân tán

- Ví dụ: khi một browser (HTTP client) yêu cầu URL `www.someschool.edu/index.html`, để người dùng gửi yêu cầu HTTP thì trước hết cần phải kết nối với server => Cần địa chỉ IP 
	1. Máy client chạy phía client side của ứng dụng DNS
	2. Trình duyệt lấy hostname từ url `www.somechool.edu` -> Chuyển đến phía client side của ứng dụng DNS
	3. DNS client gửi truy vấn kèm hostname đến máy chủ DNS
	4. Máy client cuối cùng sẽ nhận được phản hồi, bao gồm địa chỉ IP của hostname
	5. Khởi tạo kết nối TCP đến tiến trình HTTP server tại cổng 80 của địa chỉ IP đó 
=> Tốn thêm 1 delay do phải truy vấn, thực tế thì địa chỉ IP đó thường được cached tại máy chủ DNS gần đó 

- Ngoài dịch tên host thành địa chỉ IP, DNS còn cung cấp các dịch vụ sau:
	- **Bí danh của host**: Hostname phức tạp như `relay1.west-coast.enterprise.com` có thể có alias là `enterprise.com` và `www.enterprise.com` 
	- **Bí danh của mail server**
	- **Phân tán tải**: Cho phép một hostname có thể có nhiều IP khác nhau 

# Tổng quan cách hoạt động của DNS

- Như ở trên, có thể hiểu khi ứng dụng cần dịch hostname sang địa chỉ IP, nó coi DNS như là một cái hộp cung cấp dịch vụ dịch sang
- Một thiết kế đơn giản sẽ là chỉ có 1 server DNS tập trung tất cả các ánh xạ -> sẽ gây ra các vấn đề sau:
	- **Chỉ có một điểm chịu lỗi**: DNS server mà crash thì toàn bộ Internet cũng crash
	- **Lưu lượng**: DNS server sẽ cần xử lý tất cả các truy vấn (hàng trăm triệu hosts)
	- **Cơ sở dữ liệu tập trung ở xa**: Không phải tất cả các hosts đều ở gần DNS server đó 
	- **Bảo trì**: Bảo trì tốn kém 

### Cơ sở dữ liệu phân tán và phân cấp

- Để xử lý vấn đề về quy mô, DNS sử dụng lượng lớn các máy chủ được tổ chức theo phân cấp và phân tán xung quanh thế giới 
- Sẽ được chia thành 3 lớp: Root, Top-level domain, Authoritative
![[Pasted image 20251029001014.png]]

- Quy trình đơn giản khi client muốn IP cho `www.amazon.com`:
	- Client truy vấn server root để lấy TLD (com DNS server)
	- Client truy vấn com DNS server để lấy `amazon.com` DNS server
	- Client truy vấn `amazon.com` DNS server để lấy địa chỉ IP của `www.amazon.com`

- **Root DNS server**: Trên thế giới có 13 root DNS server (từ a->m). Dù ta đã gọi chúng như là một máy chủ duy nhất, nhưng thực tế chúng là một mạng lưới các máy chủ sao chép, cho mục đích bảo mật và độ tin cậy

- **Top-level domain**: Là server chịu trách nhiệm cho các tên miền `.com`, `.edu`, `.org`,... cũng như các tên miền quốc gia `.vn`, `.jp`,... 
	- Verisign Global Registry Services duy trì các server com TLD
	- Educause duy trì các server edu TLD

- **Authoritative DNS server**: Các DNS server của tổ chức, cung cấp các tên host có thẩm quyền cho các ánh xạ IP với các host của tổ chức (ví dụ web và mail)
	- Có thể được duy trì bởi các tổ chức hoặc nhà cung cấp dịch vụ

- Còn một loại DNS server quan trọng nữa là **local DNS server** (không hoàn toàn nằm trong cấu trúc phân cấp trên)
- Mỗi ISP (khu dân cư, trường đại học, công ty) có một server DNS cục bộ (còn được gọi là "default name server") 
- Khi một host tạo một truy vấn DNS, truy vấn này sẽ được gửi tới server DNS cục bộ
	- Có một vùng đệm cục bộ dịch chuyển cặp tên-địa chỉ gần nhất (tuy nhiên vẫn có thể đã bị quá hạn, chưa được cập nhật!)
	- Hoạt động giống như proxy, chuyển tiếp truy vấn vào hệ thống phân cấp

- Ví dụ truy vấn tên DNS: host tại `cis.poly.edu` muốn lấy địa chỉ IP của `gaia.cs.umass.edu`
	- **Truy vấn lặp**: 
		- Server được hỏi sẽ trả lời với tên của server sẽ có thể hỏi được tiếp
		- “Tôi không biết tên đó, nhưng có thể hỏi server này”

	- **Truy vấn đệ quy**: 
		- Đặt trách nhiệm phân giải tên lên server tên được hỏi
		- Tải nặng tại các cấp cao hơn trong hệ thống phân cấp?

### DNS caching

- Khi server tên học cách ánh xạ, nó sẽ cache ánh xạ
	- Mục cache sẽ bị quá hạn (bị xóa) sau một vài lần (TTL)
	- Các server TLD điển hình thường cache trong các server tên cục bộ
		- Do đó, các server tên gốc sẽ không thường xuyên được truy cập

- Các mục cache có thể bị quá hạn
	- Nếu host thay đổi địa chỉ IP, thì Internet sẽ có thể không biết được cho đến khi TTL hết hạn

- Cơ chế cập nhật, thông báo được đề xuất bởi chuẩn IETF
	- RFC 2136

# DNS Record (bản ghi)

- Máy chủ DNS triển khai csdl phân tán lưu trữ các **resource records** (RRs)
- Định dạng: (name, value, type, ttl)

- ttl là thời gian sống của rr, nó quyết định khi nào thì rr bị xóa khỏi cache 
- Ta sẽ tạm bỏ qua ttl, ý nghĩa của name, value phụ thuộc vào type
	- **Type = A**: name là hostname, value là địa chỉ IP
	
	- **Type = NS**: name là tên miền (`foo.com`), value là tên host của server có thẩm quyền cho tên miền này
	
	- **Type = CNAME**: name là bí danh của tên "chuẩn" (tên thật), value là tên chuẩn (`www.ibm.com` tên thật là `servereast.backup2.ibm.com`)
	
	- **Type = MX**: value là tên của mail server được kết hợp với name

# Giao thức, thông điệp DNS

- Các thông điệp **truy vấn** và **trả lời** đều có cùng định dạng thông điệp 

- Header: 
	- identification: 16 bit cho truy vấn / trả lời
	- flags:
		- Truy vấn hoặc trả lời
		- Đệ quy chờ
		- Đệ quy sẵn sàng
		- Trả lời có thẩm quyền 
![[Pasted image 20251029074202.png]]

- Cách để chèn thêm bản ghi vào trong DNS: Ví dụ tạo mới công ty Network Utopia
	- Đăng ký tên miền `networkutopia.com` tại một DNS registar
		- Cung cấp tên, địa chỉ IP của server tên có thẩm quyền (sơ cấp và thứ cấp) của bạn
		- Registrar sẽ chèn hai bản ghi RR vào trong .com TLD server: 
			1. (networkutopia.com, dns1.networkutopia.com, NS) 
			2. (dns1.networkutopia.com, 212.212.212.1, A)
	
	- Tạo bản ghi loại A vào trong server có thẩm quyền cho `www.networkuptopia.com`; bản ghi loại MX record cho mail server của bạn `networkutopia.com`

# Tấn công DNS

- **DDoS vào server gốc (root / authoritative):**
    - Gửi lưu lượng lớn để làm nghẽn server.
    - Thường khó thành công vì có lọc, caching (DNS resolver cache TLD/authoritative) và hạ tầng phân tán.

- **Tấn công vào TLD / authoritative servers:**
    - Có tác động rộng hơn nếu thành công (các miền phụ thuộc).

- **Chuyển hướng / Man‑in‑the‑middle (MITM):**    
    - Chặn/truy vấn trung gian, trả về IP giả để chuyển hướng người dùng.

- **Đầu độc cache DNS (Cache poisoning):**
	- Gửi câu trả lời giả đến DNS server; nếu DNS server cache thì sẽ phân phát kết quả sai cho client.

- **Khai thác DNS cho DDoS (DNS Amplification / Reflection):**
    - Gửi truy vấn với **IP nguồn giả mạo** (địa chỉ nạn nhân) đến resolver hoặc server có thể phản hồi lớn → phản hồi lớn tràn về nạn nhân (khuếch đại)
